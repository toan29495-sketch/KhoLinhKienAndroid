# Step122 – Strict ZIP Central Directory and EOCD verification

Date: 2026-11-03  
Baseline: exact Step121 checkpoint `KhoLinhKienAndroid-step121-backup-readback-validation-20261103.zip`; SHA-256 verified before extraction and ZIP integrity passed.

## Finding
Step121 re-opened the completed ZIP with `ZipInputStream` and verified entry contents, owner, counts and SHA-256. That pass did not independently inspect the ZIP Central Directory or End of Central Directory (EOCD). A structurally inconsistent directory could therefore remain undetected until restore.

## Changes
- Added `ZipCentralDirectoryVerifier`, a bounded random-access parser for the app's own ZIP v2 output format.
- Validates EOCD location, single-disk layout, entry counts, central-directory byte size and exact placement; rejects comments, trailing data and ZIP64 sentinels.
- Validates each Central Directory record, supported flags/method, UTF-8 entry name, no encryption, no extra fields/comments, and no nonzero external/internal attributes.
- Cross-checks every Local File Header against its Central Directory record, including name, flags and method; validates CRC and sizes when present in the local header.
- Validates each data descriptor against Central Directory CRC and sizes; verifies local entry byte ranges are contiguous, non-overlapping, and end exactly at the Central Directory.
- Compares the Central Directory entry-name set with the independently read-back and SHA-256-verified entry-name set from Step121.
- Android 10+ uses a read-only `ParcelFileDescriptor`/seekable channel while the MediaStore row remains pending. Android 8/9 uses `RandomAccessFile` on the owner-scoped partial file before rename. Any failure follows existing cleanup paths.
- The verifier is intentionally strict for ZIP files generated by this app. It rejects ZIP64, encrypted entries, unsupported compression, extra fields, comments, directories and noncanonical layout; no ZIP v2 payload format change.

## Compatibility / safety notes
- Android 10+ `openFileDescriptor(uri, "r")` must provide a seekable descriptor for the MediaStore item. If it does not, backup fails closed and the still-pending row is deleted; this behavior needs device/provider verification.
- This parser validates structure and metadata. Step121's streaming read-back remains responsible for decompression/CRC behavior, entry limits, manifest ownership, record counts and SHA-256. `ZipRestore` retains its own independent extraction and validation.
- Source lineage remains reconstructed from preserved checkpoints, not byte-for-byte restoration of lost source.
