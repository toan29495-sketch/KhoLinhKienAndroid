# Step87 – Authenticated cloud photo preview on device

## Scope
Allow a newly restored device to display private Supabase Storage photos from the part detail dialog. No schema, SQL, Storage policy, or cloud object mutation is introduced.

## Finding
`PartDialog` previously displayed only a text label for `photoPath`; no code downloaded or decoded a cloud photo for display. Thus a successful restore could preserve a valid Storage object path while the user still could not view the photo in the app.

## Change
- Added `PartPhotoPreview(photoPath, ownerId)` in `MainActivity.kt` and placed it in the part detail dialog.
- Absolute paths are treated as local pending-upload files and must exist.
- Relative paths are treated as Storage object paths. Reject absolute paths, backslashes, blank/dot/dot-dot segments, and any path whose first segment is not the currently authenticated profile's owner ID.
- Download private objects using the authenticated `downloadAuthenticatedTo` API; no public URL or unauthenticated access is used.
- Cache downloaded bytes under app cache using SHA-256 of the exact object path. Storage paths generated by the app are immutable per operation, so a path-keyed cache does not mask later object replacement.
- Bound downloaded/cached image size to 20 MiB and decode with `inJustDecodeBounds` plus `inSampleSize` to reduce memory pressure.
- Network/file/decode work runs in `Dispatchers.IO`; UI reports a readable error instead of crashing the detail dialog.

## Limits / not verified
- These are source/static/model checks only. No Android runtime, emulator, device, Room instrumentation, or real Supabase Storage session test was run.
- Cache eviction/retention policy is not yet implemented; Android may clear app cache, and a later maintenance step should bound accumulated cached images.
- Download authorization depends on existing Supabase Storage policies correctly enforcing owner-scoped access. This source validates the path prefix locally but does not replace server-side RLS/Storage policies.
- No APK build, SQL deployment, Supabase migration, GitHub push, or production operation was performed.
- Source lineage remains the reconstructed Step49–72 branch; this is not byte-for-byte recovery of the lost original source.
