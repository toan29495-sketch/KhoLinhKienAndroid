# Step117 – ZIP-temp directory shape and path hardening

Date: 2026-11-03  
Baseline: Step116 checkpoint `KhoLinhKienAndroid-step116-strict-restore-temp-owner-isolation-20261103.zip`.

## Scope
Tighten stale ZIP-temp cleanup so it only reclaims actual app-created owner-scoped UUID directories, not regular files or lookalike paths sharing the reserved prefix.

## Findings
- Step116 constrained cleanup to the active owner's prefix and canonical direct children, but the initial candidate filter did not require a directory or a canonical UUID suffix.
- A stale regular file or a directory with a malformed suffix could therefore match the reserved prefix and be passed to recursive deletion if it otherwise met the path checks.

## Changes
- Candidate enumeration now requires an actual directory and an exact `<owner-prefix><canonical UUID>` name.
- Added canonical UUID round-trip validation for the random workspace suffix generated by `UUID.randomUUID()`.
- Recheck the candidate at deletion time: canonical path must equal the listed absolute path, parent must be the canonical cache root, target must still be a directory, and name must still satisfy the owner-prefix + UUID rule.
- Retained the 24-hour age threshold, owner UUID validation, legacy unscoped-folder exclusion, immediate `finally` cleanup, ZIP bounds/checksums, and durable restore staging.
